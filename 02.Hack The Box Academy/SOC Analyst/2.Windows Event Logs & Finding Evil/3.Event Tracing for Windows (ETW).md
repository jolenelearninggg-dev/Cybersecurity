# ETW 核心筆記：Windows 的「行車紀錄器」
ETW (Event Tracing for Windows) 是作業系統層級的深度監控機制，它能捕捉那些連傳統日誌（Event Logs）都看不到的微小細節。

## 1.三大核心角色 (The Trinity)

|角色|專業術語|比喻與功能|
|---|---|---|
|發佈者|Providers|感應器：散落在系統各處（如：網路、檔案、處理器），負責產生數據。|
|控制者|Controllers|遙控器：負責開啟、關閉錄影會話。最常用的工具是 logman.exe。|
|消費者|Consumers|播放器：讀取錄製好的數據，將其轉化為人類看得懂的文字日誌。|

## 2.運作邏輯：錄影四部曲
ETW 的運作是「非即時性」的，必須先有指令才有紀錄：

  1.啟動會話 (Start Session)：管理員透過`logman.exe`下令：「啟動錄影，目標是監控某個感應器」。
  
  2.產生事件 (Generate Events)：感應器（Providers）被喚醒，開始產生原始數據。
  
  3.儲存證據 (Storage)：系統將數據存成 .ETL 格式 的原始錄影檔。
  
  4.解碼分析 (Analysis)：分析人員使用工具（消費者）打開 .ETL 檔，查看「發生了什麼事」。
  常見播放器：
  - Event Viewer： 它可以讀入 .ETL 並把它變成人類看得懂的文字日誌。
  - PowerShell (Get-WinEvent)： 用來大規模搜尋日誌內容。
  - 專業工具： 例如 EtwExplorer 或 Message Analyzer。
  
## 3. 資安研究員為什麼要學這個？
「沒錄影，就沒真相。」
- Sysmon 的爸爸：Sysmon 本質上就是一個「全天候自動化」的 ETW 消費者。它幫你簡化了開啟錄影和分析的過程。
- 深度調查：當駭客使用高階手法躲過 Sysmon 時，研究員可以手動開啟特定的 ETW 感應器（例如 `.NET` 運行時），從最底層抓到駭客的尾巴。
- 效能平衡：ETW 平時不會全部開啟（因為會讓電腦變慢），它是鑑識人員在需要「搜證」時才會啟動的重裝武力。

## 實戰常用指令 (Logman)
- `logman query -ets`：查看目前電腦有哪些「感應器」正在錄影。
- `logman query providers`：列出這台電腦上所有可以被叫醒的感應器名稱。

## 📂 實戰筆記：利用 ETW 偵測隱形攻擊
### 1.核心邏輯：Sysmon 的盲點與 ETW 的補位
 - Sysmon 的極限：容易受到 PPID Spoofing (父進程偽造) 的欺騙，且對於在記憶體中執行的 .NET 工具（無檔案攻擊）只能看到 DLL 載入，看不到具體行為。
 - ETW 的優勢：直接由核心（Kernel）或運行環境（Runtime）提供數據，難以被偽造，能記錄具體的方法呼叫（Method Calls）。
   
### 2.實戰案例：偵測 Seatbelt 的記憶體行為
`Seatbelt` 是一個常見的 .NET 調查工具，駭客常在滲透後用它來檢查系統特權。
#### 第一步：環境準備 (Sysmon 監控)
修改 Sysmon 設定，確保開啟 Event ID 7 (Image Loaded)，監控哪些程式載入了 .NET 引擎（`clr.dll` 或 `mscoree.dll`）。
- 關鍵動作：將 `onmatch="include"` 改為 exclude 以開啟全紀錄，並用 `sysmon.exe -c` 套用設定。
  
#### 第二步：啟動深度監控 (SilkETW)
當發現程式有 .NET 行為時，啟動 SilkETW 針對`Microsoft-Windows-DotNETRuntime`頻道錄影。
- 指令意義：
  ```
  DOS
  SilkETW.exe -t user -pn Microsoft-Windows-DotNETRuntime -uk 0x2038 -ot file -p C:\temp\etw.json
  ```
- 關鍵字組合 `0x2038`：同時打開 JIT、Loader 與 Interop 頻道，捕捉程式如何「翻譯」與「跨界呼叫系統 API」。

#### 第三步：執行攻擊模擬
在 PowerShell 執行 `Seatbelt.exe TokenPrivileges`。
- 此動作會讓 Seatbelt 去查詢當前使用者的權杖特權，這涉及到與 Windows 底層核心的溝通。

#### 第四步：解析 JSON 證據
檢查`etw.json`檔案，尋找程式在記憶體中「跨過橋樑」呼叫了什麼系統功能。
- 關鍵欄位：`ManagedInteropMethodName`。
- 發現證據：看到`GetTokenInformatio。
  - 這代表：即便 Seatbelt 沒有產生惡意檔案，ETW 依然抓到了它正在呼叫 Windows API 來讀取你的權杖資訊 (Token Information)。
  
  
### 總結：分析師的破案路徑
|動作階段|使用工具|觀察重點|得到的真相|
|---|---|---|---|
|表面觀察|Process Hacker|程式變綠色 (Managed)|確定該程式正在跑 .NET 代碼。|
|基礎監控|Sysmon ID 7|載入`clr.dll`|證實該程式具有執行 C# 工具的能力。|
|深度獵捕|SilkETW (0x2038)|`ManagedInteropMethodName`|抓到具體呼叫了`GetTokenInformation`，鎖定攻擊意圖。|
