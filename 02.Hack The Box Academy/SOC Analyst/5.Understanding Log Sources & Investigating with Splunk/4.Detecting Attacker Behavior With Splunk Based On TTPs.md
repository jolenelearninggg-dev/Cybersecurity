# Detecting Attacker Behavior With Splunk Based On TTPs
# 建立防禦體系
在建立監控系統時，資安分析師會併用以下兩種邏輯，來達到「滴水不漏」的防禦
## 一、 第一種方法：找「已知」的壞行為 (Spot the Known)
這就像是警察手裡拿著「通緝令」或「犯罪手法手冊」。
- 邏輯：我們已經知道駭客喜歡用哪些招數（例如：用記事本啟動 PowerShell、或是執行 mimikatz）。
- 做法：我們直接在 Splunk 寫好指令，只要有人做出這些「教科書等級」的壞事，系統就立刻報警。
- 關鍵字：TTP-based。這依賴於你對攻擊手法的了解程度（也就是你前面練習中學到的那些惡意檔名和 EventCode）。

## 二、 第二種方法：找「異常」的怪行為 (Spot the Unusual)
這就像是警察在觀察「誰的行為跟普通人不一樣」。他不一定知道你是誰，但他覺得你很怪。
- 邏輯：駭客進來後，他的行為一定會跟這台電腦平常的樣子不同。例如：這台電腦平時每天只傳 10MB 資料，今天突然傳了 10GB。
- 做法：利用數學和統計學。先讓 Splunk 學習什麼是「正常（Baseline）」，然後找出那些偏離常態的「離群值（Anomalies）」。
- 關鍵字：Statistical Analysis / Anomaly Detection。這不需要預知駭客會用什麼招數，只要他「表現異常」就會被抓到。

## 三、 為什麼要「兩者並行」？
- 只用第一種：你抓不到「新發明」的攻擊（未知威脅）。
- 只用第二種：你會被無數的「誤報（False Positives）」淹沒（例如：員工今天突然加班跑大報表，也被當成駭客）。
所以，最強的防禦是兩者結合：既盯著已知的壞招，也隨時注意不尋常的風吹草動。

|策略名稱|英文術語|核心邏輯|比喻|
|---|---|---|---|
|找「已知」壞行為|Spot the Known (TTP-based)|根據已知的駭客攻擊手法（TTPs）設定規則。|拿著 **「通緝令」** 在門口對照臉部特徵抓人。|
|找「異常」怪行為|Spot the Unusual (Anomaly-based)|利用統計學和數學，找出偏離「正常基準線」的行為。|觀察人群中 **「行為舉止怪異」** 的人（例如：大家都在走路，只有他在爬行）。|



# Crafting SPL Searches Based On Known TTPs
# 基於 TTP 的實戰獵捕範例 (Known TTPs)

## 範例 1：利用原生指令進行偵察 (Reconnaissance)
駭客行為 (TTP)： 駭客進入系統後，會「就地取材 (Living off the Land)」，使用 Windows 內建工具來摸索環境（我是誰？這台電腦叫什麼？網域裡還有誰？）。
- 關鍵 EventID： EventCode=1 (程式啟動)
- 重點監控名單：
  - `whoami.exe` (查詢權限)
  - `hostname.exe` (查詢機器名)
  - `ipconfig.exe` / `netstat.exe` (查詢網路)
  - `net.exe` (查詢使用者/網域)
  - `tasklist.exe` (查詢運行中的程式)

### Splunk 搜尋邏輯：
```
Splunk SPL

index="main" sourcetype="WinEventLog:Sysmon" EventCode=1 
(Image=*\\ipconfig.exe OR Image=*\\net.exe OR Image=*\\whoami.exe OR Image=*\\hostname.exe)
| stats count by Image, CommandLine 
| sort - count
```
- 分析師的警覺點 (Red Flags)：
  - 1.異常頻率： 正常使用者很少執行這些指令。若短時間內 count 很高（例如 19 次），極度可疑。
  - 2.敏感參數：
    - `whoami /priv`：駭客正在檢查有沒有提權機會。
    - `net users` /`domain`：駭客正在調查網域帳號，準備橫向移動。
