# Detecting Attacker Behavior With Splunk Based On TTPs
在建立監控系統時，資安分析師會併用以下兩種邏輯，來達到「滴水不漏」的防禦
### 一、 第一種方法：找「已知」的壞行為 (Spot the Known)
這就像是警察手裡拿著「通緝令」或「犯罪手法手冊」。
- 邏輯：我們已經知道駭客喜歡用哪些招數（例如：用記事本啟動 PowerShell、或是執行 mimikatz）。
- 做法：我們直接在 Splunk 寫好指令，只要有人做出這些「教科書等級」的壞事，系統就立刻報警。
- 關鍵字：TTP-based。這依賴於你對攻擊手法的了解程度（也就是你前面練習中學到的那些惡意檔名和 EventCode）。

### 二、 第二種方法：找「異常」的怪行為 (Spot the Unusual)
這就像是警察在觀察「誰的行為跟普通人不一樣」。他不一定知道你是誰，但他覺得你很怪。
- 邏輯：駭客進來後，他的行為一定會跟這台電腦平常的樣子不同。例如：這台電腦平時每天只傳 10MB 資料，今天突然傳了 10GB。
- 做法：利用數學和統計學。先讓 Splunk 學習什麼是「正常（Baseline）」，然後找出那些偏離常態的「離群值（Anomalies）」。
- 關鍵字：Statistical Analysis / Anomaly Detection。這不需要預知駭客會用什麼招數，只要他「表現異常」就會被抓到。

### 三、 為什麼要「兩者並行」？
- 只用第一種：你抓不到「新發明」的攻擊（未知威脅）。
- 只用第二種：你會被無數的「誤報（False Positives）」淹沒（例如：員工今天突然加班跑大報表，也被當成駭客）。
所以，最強的防禦是兩者結合：既盯著已知的壞招，也隨時注意不尋常的風吹草動。

|策略名稱|英文術語|核心邏輯|比喻|
|---|---|---|---|
|找「已知」壞行為|Spot the Known (TTP-based)|根據已知的駭客攻擊手法（TTPs）設定規則。|拿著 **「通緝令」** 在門口對照臉部特徵抓人。|
|找「異常」怪行為|Spot the Unusual (Anomaly-based)|利用統計學和數學，找出偏離「正常基準線」的行為。|觀察人群中 **「行為舉止怪異」** 的人（例如：大家都在走路，只有他在爬行）。|



# Crafting SPL Searches Based On Known TTPs
## 範例 1：利用原生指令進行偵察 (Reconnaissance)
### 駭客行為 (TTP)： 
駭客進入系統後，會「就地取材 (Living off the Land)」，使用 Windows 內建工具來摸索環境（我是誰？這台電腦叫什麼？網域裡還有誰？）。
- 關鍵 EventID： EventCode=1 (程式啟動)
- 重點監控名單：
  - `whoami.exe` (查詢權限)
  - `hostname.exe` (查詢機器名)
  - `ipconfig.exe` / `netstat.exe` (查詢網路)
  - `net.exe` (查詢使用者/網域)
  - `tasklist.exe` (查詢運行中的程式)

### Splunk 搜尋邏輯：
```
Splunk SPL

index="main" sourcetype="WinEventLog:Sysmon" EventCode=1 
(Image=*\\ipconfig.exe OR Image=*\\net.exe OR Image=*\\whoami.exe OR Image=*\\hostname.exe)
| stats count by Image, CommandLine 
| sort - count
```
- 分析師的警覺點 (Red Flags)：
  - 1.異常頻率： 正常使用者很少執行這些指令。若短時間內 count 很高（例如 19 次），極度可疑。
  - 2.敏感參數：
    - `whoami /priv`：駭客正在檢查有沒有提權機會。
    - `net users` /`domain`：駭客正在調查網域帳號，準備橫向移動。

## 範例 2：利用可信網域下載惡意載荷 (Payload Hosting)

### 駭客行為 (TTP)：
駭客將惡意腳本或工具上傳至 GitHub (`https://www.google.com/url?sa=E&source=gmail&q=raw.githubusercontent.com`)。因為大多數公司會將 GitHub 列入防火牆白名單，駭客藉此避開偵測，讓受害電腦直接從雲端下載並執行惡意代碼。
- 關鍵 EventID： EventCode=22 (DNS Query - 紀錄電腦正在查詢哪個網址)
- 重點監控名單：
  - `raw.githubusercontent.com`(GitHub 原始碼路徑)
  - `pastebin.com`(剪貼簿服務)
  - `discordapp.com` (通訊軟體附件)

### Splunk 搜尋邏輯：
```
Splunk SPL
index="main" sourcetype="WinEventLog:Sysmon" EventCode=22 QueryName="*github*"
| stats count by Image, QueryName
```
*(註：使用 by Image, QueryName 是為了同時鎖定「誰連的」以及「去哪裡」。)*
- 分析師的警覺點 (Red Flags)：
  - 1.異常組合： 看到 powershell.exe 或 cmd.exe 連向 raw.githubusercontent.com。這通常代表正在下載並執行「無檔案攻擊 (Fileless)」腳本。
  - 2.低頻率 (Rareness)： 正常系統更新的次數會很多（High Count），但駭客下載工具的動作通常只有幾次（Low Count）。


## 範例 3：偵測 PsExec 遠端執行行為 (橫向移動)
### 駭客行為 (TTP)：
PsExec 原本是管理員用來遠端維護的工具，但因為它可以讓駭客在另一台電腦上安裝服務、執行指令，而且通常具備最高系統權限 (SYSTEM)，所以常被駭客使用。
#### 偵測維度 A：註冊表修改 (EventCode 13)
- 核心邏輯：監控系統服務管理員 (services.exe) 去改動「服務執行路徑 (ImagePath)」。

### Splunk 搜尋邏輯：
```
Splunk SPL
index="main" EventCode=13 Image="*services.exe" TargetObject="*ImagePath"
| rex field=Details "(?<file_name>[^\\\]+)$"
| stats count by file_name, ComputerName
```
- 分析師警覺：利用 rex 切出檔案名稱，看哪些服務檔案只出現 1-2 次（如 PSEXESVC.exe 或奇怪的 .exe）。

#### 偵測維度 B：檔案建立 (EventCode 11)

- 核心邏輯：PsExec 執行時會產生一個臨時服務檔案。
- 分析師警覺：在 C:\Windows\ 目錄下突然出現 PSEXESVC.exe 檔案。

#### 偵測維度 C：具名管道 (EventCode 17/18)
- 核心邏輯：這是 PsExec 的「通訊電波」。它會建立一個名字叫 \PSEXESVC 的管道。
- 分析師警覺：只要看到 PipeName 包含 PSEXESVC，基本上就是 PsExec 的鐵證。

## 範例 4：偵測壓縮檔的使用 (工具傳輸或資料外洩)
### 駭客行為 (TTP)：
駭客通常會利用壓縮檔（.zip, .rar, .7z）來進行兩件事：

1.橫向工具傳輸：把整套攻擊工具包（如 BloodHound）打包傳入受害主機，避免單個檔案被過濾。

2.資料外洩 (Exfiltration)：將偷來的機密文件先壓縮打包，以便快速傳回駭客伺服器並減少流量特徵。

- 關鍵 EventID： EventCode=11 (FileCreate - 檔案建立紀錄)
- 重點監控對象： 所有結尾為 .zip, .rar, .7z 的檔案。

### Splunk 搜尋邏輯：
```
Splunk SPL
index="main" EventCode=11 (TargetFilename="*.zip" OR TargetFilename="*.rar" OR TargetFilename="*.7z")
| stats count by ComputerName, User, TargetFilename
| sort - count
```
- 分析師的警覺點 (Red Flags)：

  1.檔名異常：直接出現敏感工具名稱（例如 BloodHound.zip, Procdump.zip）。

  2.使用者異常：由 SYSTEM 或 Administrator 帳號建立的壓縮檔（系統帳號通常不會手動壓 ZIP）。

  3.路徑異常：壓縮檔出現在 C:\Windows\Temp 或 C:\Users\Public 等公共/臨時資料夾。

  4.行為異常：由 powershell.exe 或 cmd.exe 發起壓縮動作（一般人多使用圖形介面 7-Zip 或 WinRAR）。




## 範例 5：偵測利用 PowerShell 或 瀏覽器下載惡意載荷 (工具傳入)
### 駭客行為 (TTP)：

1.腳本下載：利用 PowerShell 遠端抓取工具（如 SharpHound）直接存入磁碟。

2.誘騙下載：誘導使用者透過 Edge 瀏覽器下載偽裝檔案（如 randomfile.exe）。

- 關鍵 EventID： EventCode=11 (FileCreate - 檔案建立紀錄)
- 重點監控對象： 發起程式為 powershell.exe 或帶有網路下載標籤的檔案。
- Splunk 搜尋邏輯：
  - 監控 PowerShell： `index="main" EventCode=11 Image="*powershell.exe*"`
  - 監控瀏覽器下載標籤： `index="main" EventCode=11 Image="*msedge.exe" TargetFilename=*"Zone.Identifier"`
  *(註：Zone.Identifier 是 Windows 幫網路下載檔案貼上的「外來者標籤」，是追蹤檔案來源的鐵證。)*

- 分析師的警覺點 (Red Flags)：

  1.敏感工具出現：下載區出現 SharpHound, comsvcs.dll, mimikatz 等字眼。

  2.外來者標籤：看到從 Edge 下載了拼錯名字或功能不明的 .exe 或 .dll。



## 範例 6：偵測來自「異常路徑」的程式執行 (路徑偵防)
### 駭客行為 (TTP)：
駭客通常會直接在 下載資料夾 (Downloads) 或 暫存區 (Temp) 執行工具，因為這些地方不需要管理員權限即可寫入並執行，且能避開標準安裝路徑的監控。
- 關鍵 EventID： EventCode=1 (ProcessCreate - 程式啟動紀錄)
- 重點監控對象： 發生在非標準安裝目錄（如 C:\Users\...\Downloads）的執行動作。
#### Splunk 搜尋邏輯：
```
Splunk SPL
index="main" EventCode=1 | regex Image="C:\\\\Users\\\\.*\\\\Downloads\\\\.*" 
| stats count by Image
```
*(註：使用 regex 與 .* 萬用字元可以一次鎖定所有使用者的下載路徑。)*

- 分析師的警覺點 (Red Flags)：

  1.稀有事件 (Rareness)：在下載區執行且 count 只有 1 的程式（如 SharpHound.exe）。

  2.合法工具亂跑：看到 PsExec64.exe 出現在一般使用者的下載資料夾中。





## 範例 7：偵測在 Windows 目錄以外建立的執行檔 (路徑排除法)
### 駭客行為 (TTP)：
為了躲避對系統核心目錄（C:\Windows\）的嚴密監控，駭客會將惡意程式或劫持用的 DLL 藏在使用者目錄或應用程式路徑中。
- 關鍵 EventID： EventCode=11 (FileCreate - 檔案建立紀錄)
- 核心策略： 「排除已知，鎖定未知」。

#### Splunk 搜尋邏輯：
```
Splunk SPL
index="main" EventCode=11 (TargetFilename="*.exe" OR TargetFilename="*.dll") 
TargetFilename!="*\\windows\\*"
| stats count by User, TargetFilename | sort + count
```
*(註：!= 排除掉正常的系統路徑，讓分析師能專注於那些出現在「非系統區」的檔案。)*
- 分析師的警覺點 (Red Flags)：

  1.位置異常：執行檔出現在 \AppData\ 或 \Public\ 等易寫入路徑。

  2.權限錯位：SYSTEM 帳號在一般使用者的個人目錄下建立執行檔。



## 範例 8：偵測偽裝與拼寫錯誤 (Typosquatting)
### 駭客行為 (TTP)：
駭客故意將惡意程式命名為與系統工具極度相似的名字（例如將 PSEXESVC.exe 改成 PSEXECSCVCS.exe），利用人類視覺盲點避開肉眼檢查。
- 關鍵 EventID： EventCode=1 (ProcessCreate - 程式啟動紀錄)
- 重點監控欄位： 同時檢查 Image (子程序) 與 ParentImage (父程序)。

#### Splunk 搜尋邏輯：
```
Splunk SPL
index="main" EventCode=1 (Image="*psexe*" OR ParentImage="*psexe*") 
NOT (Image="*PSEXESVC.exe" OR Image="*PsExec64.exe")
| table Image, CommandLine, ParentImage, ParentCommandLine
```
- 分析師的警覺點 (Red Flags)：

  1.拼字陷阱：發現檔名多了一個字母、少了一個字母或順序錯誤。

  2.異常父子關係：看到拼錯名字的程式作為「爸爸」，啟動了 PowerShell 去下載腳本。



## 範例 9：偵測非標準連接埠通訊 (網路異常)
### 駭客行為 (TTP)：
駭客常避開標準的 80 (HTTP) 或 443 (HTTPS) 埠，改用非標準埠（如 8080, 5355, 3389）來進行指令下達 (C2) 或在內網中進行橫向移動。
- 關鍵 EventID： EventCode=3 (NetworkConnection - 網路連線紀錄)
- 核心策略： 排除流量巨大的標準埠，尋找異常的連線行為。

#### Splunk 搜尋邏輯：
```
Splunk SPL
index="main" EventCode=3 
NOT (DestinationPort=80 OR DestinationPort=443 OR DestinationPort=22 OR DestinationPort=21) 
| stats count by SourceIp, DestinationIp, DestinationPort | sort - count
```
- 分析師的警覺點 (Red Flags)：

  1.高頻率異常 Port：例如 Port 5355 (LLMNR) 連線過多，可能代表正遭受投毒攻擊。

  2.內部橫向移動：看到內網機器頻繁連向其他機器的 Port 3389 (遠端桌面)。
