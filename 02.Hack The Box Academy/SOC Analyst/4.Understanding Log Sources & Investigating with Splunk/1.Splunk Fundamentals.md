# 🛡️ Splunk 藍隊資安筆記
## 一、 Splunk 是什麼？
Splunk 在資安領域（SIEM）的角色就像是 「機器資料的 Google」。
- 目的：將分散在各處（伺服器、防火牆、防毒軟體）那種亂七八糟的純文字日誌（Logs），轉化為可以搜尋、統計、畫圖的「數位證據」。
- 使用時機：
  - 威脅獵捕 (Threat Hunting)：主動搜尋異常行為（例如：誰在半夜登入？）。
  - 資安鑑識 (Forensics)：發生入侵後，回溯駭客進場的路徑。
  - 即時監控：建立儀表板，當攻擊發生時自動噴出告警。
  
## 二、 Splunk 的「消化系統」：三大核心組件
### 1.Forwarder (轉發器)：
- 像「搬運工」，裝在目標電腦上，負責把 Log 傳回 Splunk。
- 關鍵概念：Universal Forwarder (UF) 最輕量，只搬資料不思考。
### 2.Indexer (索引器)：
- 像「倉庫與圖書館員」，負責把資料壓縮、存檔、編索引。
- 關鍵概念：搜尋速度快不快，全看 Indexer 的效能。
### Search Head (搜尋頭)：
- 像「展示櫃與翻譯官」，這是你（分析師）操作網頁介面的地方。
- 關鍵概念：在此輸入 SPL 語法，它會去叫 Indexer 把結果找出來。
  
## 三、 SPL 語法常用指令
SPL 的邏輯是 「由左往右，層層過濾」：
|指令|作用|藍隊實戰場景|
|---|---|---|
|`index`|指定資料庫|縮小範圍，例如 `index="main"`。|
|`stats dc()`|唯一值計數|算一個帳號登入過幾台「不同的」電腦。|
|`where/search`|條件過濾|找出 `period < 600`（10分鐘內）的異常活動。|
|`table`|格式化輸出|只顯示你關心的欄位（時間、帳號、IP）。|
|`dedup`|去除重複|忽略重複的日誌，只看獨特的行為。|
|`eval`|建立新欄位|把兩個標籤（IP 或 Host）揉成同一個欄位。|
|`rex`|正規表示式|從亂碼中強行切出你要的資料（如：病毒 ID）。|

## 四、 為什麼 App 會壞掉？
當你發現儀表板「沒資料」時，通常是以下兩個問題：
### 1.Macro (巨集) 沒設對：
 - App 預設找 index=default，但你的資料在 index=main。
 - 修法：去 Settings -> Advanced Search -> Macros 修改定義。
### 2.欄位名稱不對齊 (Field Mapping)：
 - App 想找 dest_ip，但你的資料叫 DestinationIp。
 - 修法：使用 rename 指令，或是直接修改 App 儀表板裡的 SPL。
 
## 五、 關鍵 EventCode
在分析 Windows 資料時，這兩個代碼是你的「起手式」：
- EventCode 4768：Kerberos 領門票（TGT）。看到大量失敗 = 暴力破解。
- EventCode 4624：登入成功。搭配 dc(ComputerName) = 偵測橫向移動。
