# Get-WinEvent
PowerShell 中專門用來從海量日誌中翻找證據的強力指令，能讓你徹底擺脫讀取緩慢、動不動就當掉的傳統圖形化事件檢視器（Event Viewer）。<br>
它最厲害的地方在於能同時處理本地、遠端、甚至離線的 .evtx 備份檔，並完美支援 Sysmon 與 ETW 等深度監控數據，配合靈活的過濾邏輯（如 Hashtable），讓你能在幾秒鐘內從數百萬筆雜訊中，直接鎖定駭客非法登入或惡意程式在記憶體偷跑的關鍵瞬間。

### 一：基礎語法

看到 -ListLog：知道這是在檢查「有哪些日誌可以用」。
第一階段：偵察 (看看家裡有什麼)
```
PowerShell
# 列出所有日誌清單，看看哪邊資料多 (RecordCount)
Get-WinEvent -ListLog * | Select-Object LogName, RecordCount, IsEnabled | Format-Table
```

看到 -FilterHashtable：知道這是在進行「快速過濾」。
第二階段：快速過濾 (FilterHashtable)
```
PowerShell
# 語法：@{日誌名; ID; 開始時間}
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-Sysmon/Operational'; ID=1,3
```

第三階段：深度挖掘 (屬性索引)
```
Properties[21]：在 Sysmon ID 1 中代表 「父行程的指令內容」。
```
實戰關鍵字： -enc。看到這個通常代表有惡意 PowerShell 加密指令在跑。




看到 ID=1,3：知道這是在找「特定的行為（進程、網路）」。

第二級：會「套模板」修改 (目前目標)
這就是為什麼我幫你整理筆記的原因。在工作時，你會打開筆記，複製一段指令，然後只改你想改的部分。

範例：你有一段找 System 日誌的指令，你只需要知道把 'System' 改成 'Security' 就能找登入紀錄。這就是所謂的「填空式」操作。

第三級：知道「為什麼」要這樣搜 (進階能力)
這比記住指令更重要。

為什麼要找 Properties[21]？因為那是父行程指令。

為什麼要找 -enc？因為駭客愛用加密指令。

這種「資安邏輯」才是你腦袋要記的東西，至於指令怎麼寫，交給筆記或 Google 就好。


先看大方向：用 Get-WinEvent -ListLog 確認有沒有日誌可查。

鎖定目標：用 FilterHashtable 找特定的 ID (1=進程, 3=網路, 7=DLL, 10=權限)。

拆穿偽裝：

看到沒聽過的 .exe 呼叫 lsass.exe ➔ ID 10 (偷密碼)。

看到 calc.exe 載入奇怪路徑的 DLL ➔ ID 7 (劫持)。

看到 spoolsv.exe 突然變綠色且呼叫敏感 API ➔ ETW (記憶體注入)。
