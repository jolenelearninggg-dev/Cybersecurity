# 實戰演練
### 1. 工具心法：Event Viewer vs. Get-WinEvent
- Event Viewer (GUI)：適合深度查看單一事件的「細節」與「XML 結構」。記住：要看證據檔案必須使用 「開啟儲存的紀錄 (Open Saved Log)」。
- Get-WinEvent (PowerShell)：資安專家的「重裝武器」。最強大的地方在於能使用 萬用字元 \* 同時橫跨多個 .evtx 檔案進行大規模過濾。

## 2. 關鍵技術：將 XML 轉化為過濾邏輯

#### 方法二：
當你不知道 Properties[n] 該填多少時，先在 Event Viewer 打開 「XML 檢視 (XML View)」：
- 所有數據都藏在 <EventData> 的 <Data> 標籤中。
- 索引規則：從上往下數，第一個標籤是 [0]，以此類推。
- 本次範例 (Sysmon ID 7)：
  - [4] 是 Image (執行的程式路徑)。
  - [5] 是 ImageLoaded (載入的 DLL 路徑)。
  - [12] 是 Signed (是否有數位簽章，false 代表極度可疑)。


## 3. 實戰案例分析：DLL 劫持 (DLL Hijacking)
### 題目："By examining the logs located in the "C:\Logs\DLLHijack" directory, determine the process responsible for executing a DLL hijacking attack. Enter the process name as your answer.
- 行為特徵：合法程式載入了不該出現在該路徑的 DLL。
- 獵捕關鍵字：
  - ID 7：監控模組載入動作。
  - Signed: false：排除有原廠認證的合法檔案，讓惡意 DLL 現形。
  - 路徑異常：注意像 C:\ProgramData 或 C:\Users\ 這種任何人都能寫入的資料夾，如果裡面出現了系統級的 .exe 或 .dll，這就是典型的 DLL 側載 (Side-loading)。

## 4. PowerShell 搜尋方式

萬用過濾公式：<br>
- `Get-WinEvent -Path '路徑\*' | Where-Object { $_.Id -eq [ID] -and $_.Properties[n].Value -like "*關鍵字*" } | Select-Object TimeCreated, @{N='標題';E={$_.Properties[n].Value}} | Format-List`
- `Get-WinEvent -FilterHashtable @{Path='路徑\*'; ID=[ID]} | Where-Object {$_.message -like "*關鍵字*"} | Format-List`
- 在自定義欄位中，N='名稱' 與 E={邏輯} 必須用等號連接。
- Format-List 面加上*，這個星號 * 代表 「顯示所有屬性」，這在找尋隱藏證據時非常有用喔！
- FilterHashtable > 快速過濾要針對的eventID
- $_.message -like "關鍵字*" > 找到日誌中有包含相關關鍵字的

### 搜尋範例
```
Get-WinEvent -Path 'C:\Tools\chainsaw\EVTX-ATTACK-SAMPLES\Lateral Movement\*' | Where-Object {$_.Id -eq 5142 -and $_.Properties[4].Value -like "*PRINT*"} | Select-Object TimeCreated, Message | Format-List
# Format-List 後面加上*，這個星號 * 代表 「顯示所有屬性」，這在找尋隱藏證據時非常有用喔！
```

## 實戰演練2
### By examining the logs located in the "C:\Logs\PowershellExec" directory, determine the process that executed unmanaged PowerShell code. Enter the process name as your answer. Answer format: _.exe

### 解題思路：
- ID 7 (ImageLoaded) > 哪一個程式（Image），載入了哪一個工具包
- clr.dll（.NET 的心臟）
- PowerShell 並不是一個獨立運作的程式，它是建立在 .NET Framework 之上的。而 CLR (Common Language Runtime) 就是 .NET 的核心引擎，負責管理記憶體、執行程式碼。
  - `clr.dll` 就是這個引擎的實體。
  - 任何程式（.exe）如果想要執行 PowerShell 指令或是 C# 程式碼，就必須先在自己的肚子裡「啟動」這個 .NET 引擎。
  - 啟動引擎的第一步，就是 載入 `clr.dll`。
- *誰在不該用到 .NET 的時候，偷偷啟動了 .NET 引擎？*
<br>
- 搜尋指令
  - `Get-WinEvent -Path 'C:\Logs\PowershellExec\PowershellExec.evtx' | Where-Object {$_.Id -eq 7 -and $_.Properties[5].Value -like "*clr.dll*"} | Format-List`

## 實戰演練4
### 題目：By examining the logs located in the "C:\Logs\Dump" directory, determine the process that performed an LSASS dump. Enter the process name as your answer. Answer format: _.exe

### 解題思路：
- LSASS (Local Security Authority Subsystem Service)憑證（可能是雜湊後的 Hashed 密碼，有時甚至是明文）會暫時存放在 lsass.exe 這個程序的記憶體
- Dump 把記憶體裡的資料整塊拷貝出來，存成一個檔案（例如 lsass.dmp）
- ID 10 一個程序去存取（Access）另一個程序
- TargetImage: `lsass.exe` > 太多雜訊，再加上非 `svchost.exe`
<br>
- 搜尋指令
  - `Get-WinEvent -FilterHashtable @{Path='C:\Logs\Dump\LsassDump.evtx'; ID=10} | Where-Object {$_.Properties[8].Value -like "*lsass*" -and $_.Properties[5].Value -notlike "*svchost.exe*"} | Format-List`

## 實戰演練6
### 題目：By examining the logs located in the "C:\Logs\StrangePPID" directory, determine a process that was used to temporarily execute code based on a strange parent-child relationship. Enter the process name as your answer. Answer format: _.exe
### 解題思路：
- PPID Spoofing (父程序 ID 欺騙)
- Parent-Child Relationship（父子關係）
- Sysmon Event ID 1 (Process Creation)
  - 這是最強大的武器。它不只記錄了誰被啟動（Image），還記錄了誰是它的父親（ParentImage），以及啟動時的指令（CommandLine）。
- 找到**不符合常理的配對**
