## 第一部分：Windows 事件記錄基礎 (Basics)
Windows 事件記錄是系統內建的日誌系統，記錄了系統組件、應用程式、服務等的運作狀況。主要分為五大類：

  1. Application (應用程式)：軟體錯誤或資訊。
  2. Security (安全性)：資安分析的核心，記錄登入、權限變更、資源存取。
  3. Setup (安裝)：系統更新或安裝紀錄。
  4. System (系統)：驅動程式、系統啟動/關閉、硬體問題。
  5. Forwarded Events (轉發事件)：從其他電腦傳送過來的集中式日誌。
  
##### 解構一個事件 (Anatomy)：
 - 每個事件都有 Event ID (唯一識別碼)、Level (嚴重程度：資訊、警告、錯誤、關鍵)、Source (來源軟體) 和 Computer (主機名)。

### 進階查詢與 XML
XML 查詢：從「關鍵字搜尋」進化到「精準過濾」<br>
在事件檢視器的傳統介面，你只能搜 Event ID、日期、關鍵字。<br>
但如果你想搜：「找出所有來源 IP 為 192.168.1.100，且 Logon Type 為 10 的 RDP 登入」，傳統介面做不到。<br>

###### XML 分頁讓你用 XPath 語法直接對準數據包的核心：
```
<QueryList>
  <Query Id="0" Path="Security">
    <Select Path="Security">*[EventData[Data[@Name='TargetLogonId']='0x3e7']]</Select>
  </Query>
</QueryList>
```
 - 精準度：可以直接針對 XML 標籤內的數值篩選。
 - 效能：在數十萬筆日誌中，XML 篩選速度遠快於肉眼掃視。
 - 複雜性：可以寫出 A 條件 AND B 條件 的複合式邏輯。

### SACL (System Access Control List) — 「系統稽核清單」
如果把檔案比喻成一扇門，SACL 就是這扇門上面的 「連動監視器」。
 - 它的功能：決定「誰」對這個物件做了「什麼事」的時候，系統要寫下日誌 (Log)。
 - 與 DACL 的差異：
   - DACL (一般說的 ACL)：門禁卡。決定誰能進去、誰能改檔案。
   - SACL：錄影機。不影響權限，只決定要不要錄影（稽核）。
 - 資安關鍵點：
   - Event ID 4907：有人修改了 SACL。
   - 分析意義：如果駭客想「毀屍滅跡」，他會改掉 SACL 讓系統停止錄影，這樣他偷看檔案就不會留下 ID 4663 (物件存取) 的紀錄。
     
### SDDL (Security Descriptor Definition Language) — 「權限速記代碼」
這是一套為了讓電腦讀起來很快、存起來很小的 「權限縮寫語法」。<br>
它的樣子：看起來像亂碼，例如 `D:(A;;FA;;;BA)`。

##### 結構拆解 (核心四元素)：

 - O: (Owner) — 誰是這台電腦/檔案的主人。
 - G: (Group) — 屬於哪個群組。
 - D: (DACL) — 誰能存取。
 - S: (SACL) — 誰要被稽核。
   
常見代碼含義 (看一眼就有專業感)：
 - BA：Built-in Administrators (管理員)。
 - SY：Local System (系統帳號)。
 - FA：File All Access (全權限)。
 - A：Allow (允許)。
